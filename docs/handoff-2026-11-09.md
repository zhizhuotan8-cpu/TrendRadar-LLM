```powershell
$env:PYTHONDONTWRITEBYTECODE = '1'
$env:PYTHONUTF8 = '1'
$env:LITELLM_LOCAL_MODEL_COST_MAP = 'True'
.\.venv\Scripts\python.exe -m pytest tests -q

```

依赖按 `uv.lock` 安装。早期直接解析最新间接依赖曾产生 MCP/Pydantic 导入失败，使用锁文件后恢复。
pytest 是额外安装的测试依赖；运行 `uv sync` 清理环境后可能需要重新安装。

运行命令、环境变量、配置和恢复操作的完整说明统一放在
[部署文档](intelligence-agent.md)。配置入口是 `config/intelligence.yaml`。
当前新功能读取启动进程环境变量，未实现自动加载 `.env`；不要让用户只填旧 `config.yaml` 后期待新入口读取。

凭据需求：

- 每日分析：`AI_API_KEY`、有效的 `AI_MODEL`，必要时 `AI_API_BASE`。
- 原文读取：`JINA_API_KEY`；匿名访问在本次验证中失败。
- 联网追问：`BRAVE_SEARCH_API_KEY`。
- 飞书发送：`FEISHU_WEBHOOK_URL`。
- 网络需要时：`HTTPS_PROXY`。

这些凭据未写入仓库。不要输出密钥或将真实密钥加入交接文档。
代码中的默认模型名是早期配置；部署时应显式填写服务商当前可用模型，并实际验证接口兼容性。

## 实现入口

| 模块 | 责任 |
| --- | --- |
| `trendradar/intelligence/store.py` | 独立 SQLite，schema 版本 5，事务迁移、来源、正文读取记录 |
| `collection.py` / `ingestion.py` | RSS、可选 NewsNow 热榜、来源归一化及正文入库 |
| `article_reader.py` | 共享 Jina Reader；MCP 旧入口继承该服务 |
| `analysis.py` | 结构化筛选、逐字引文校验、事件/变化标识和置信度 |
| `budget.py` | 每轮独立的调用次数、预留输出 token 和时长预算 |
| `briefing.py` | 简报持久化、HTML 转义、投递状态与已送达版本覆盖记录 |
| `runtime.py` / `__main__.py` | 每日流水线、飞书适配、daily/daemon/serve/retry 入口 |
| `locking.py` | 单个每日 worker 的跨平台进程锁 |
| `search.py` / `chat.py` | Brave 搜索、已读资料检索、引用校验、服务端聊天历史 |
| `web.py` | 本机 HTTP 网页、报告、聊天接口及请求令牌 |

主要测试位于 `tests/test_intelligence_*.py`，现有 MCP、存储和时间测试也纳入全套测试。

## 需要保持的行为与实际限制

- 来源 URL 去重与事件合并分开；首次发现时间不能被重复采集覆盖，发布时间允许未知。
- 正文失败保存错误状态且正文为空，RSS 摘要不能冒充读过的原文。
- 分析引用实际提供的快照，引文必须逐字匹配；该检查不证明模型推理语义正确。
- 事件合并依赖模型生成 key，低于 0.85 置信度暂不入选。现阶段没有人工复核界面。
- 简报最多 10 项，同日报告不重新生成。失败报告保留，只有发送成功才计入覆盖记录。
- 超时、部分批次成功及进程中断可能产生 `uncertain`，需要显式重试；无法保证外部 exactly-once。
- daemon 从北京时间 09:00 开始运行，实际送达会晚于开始时间；进程需常驻，尚未安装系统服务。
- 网页默认只监听本机，没有多用户登录或公网部署配置；网页进程和 daemon 分别启动。
- 模型候选事件最多 50 个；聊天检索最近 100 个正文快照，使用文本匹配和正文节选，不是向量检索。
- token 计数为预留输出上限，不是实际计费；底层请求超时不是强制中断任意第三方代码的保证。
- 默认来源已经过网络可用性检查，但质量排序、重要消息召回和误合并率尚未实测。
